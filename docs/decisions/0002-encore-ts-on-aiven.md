# 0002 — Backend: Encore.ts, self-hosted, on Aiven for PostgreSQL

Supersedes `0001-backend-runtime.md`.

## Context

The product is Silta (see `AGENTS.md`). We want typed endpoints, a generated
frontend client, local infrastructure without setup, and a real use of Aiven,
whose tech-challenge prize weighs "meaningful use" at 40%.

## Decision

- The backend is an **Encore.ts** app in `backend/`. The Python/FastAPI scaffold
  is deleted.
- One PostgreSQL database, `silta`, with **pgvector**. Locally Encore provisions
  it; in the cloud it is **Aiven for PostgreSQL**.
- **Self-hosted, not Encore Cloud.** Encore Cloud provisions its own database, so
  we build an image with `encore build docker` and point
  `backend/infra.config.json` at Aiven.
- **Same-region rule.** The app and the database run in the same cloud and
  region. Plan A: Aiven Runtime next to the database (it wraps our GHCR image,
  see `docs/deployment.md`). Plan B: a
  container host in the same region. Never split them across regions.
  Aiven Runtime has no Finnish region, so both run in `google-europe-west4`.
- The frontend talks to the API only through the client generated by
  `encore gen client` (`make api`). `contracts/openapi.json` is gone.
- Redis is dropped until a feature needs ephemeral state (then: Aiven for Valkey).

## Consequences

- Every developer and CI needs the Encore CLI and Docker.
- The self-hosted image does not run migrations: apply them first
  (`make migrate-aiven`).
- Aiven has no object storage: small audio clips go into Postgres `bytea` until
  size becomes a problem.
- LLM calls move to the `llm` Encore service (Gemini); the OpenRouter/mistral
  provider registry was not ported.

## Revisit when

Aiven's runtime cannot host the image and no same-region host is available, or
the hackathon ends and the app needs a long-term home.
